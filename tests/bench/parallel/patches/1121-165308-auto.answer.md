`--budget` は、月×カテゴリの合計が予算を超えた分を stderr に警告するだけのオプションです。stdout と終了コードは変わりません。コードは変更していません。

## 予算 JSON の形式(`core.py:87-122`)

```json
{
  "default": {"food": 1500, "rent": 90000},
  "months": {"2026-11": {"food": 1000}}
}
```

- `default` は全月共通の上限です。
- `months` のキーは `YYYY-MM` で、`default` を**カテゴリ単位で上書き**します。`for_month` は `{**default, **months[月]}` を返します。
  - 上の例の 2026-11 では food が 1000、rent は default の 90000 のままです。
  - `months` に書いていない月は `default` だけが適用されます。
- `default` と `months` はどちらも省略できます。
- 金額は 0 以上の整数です。bool や小数、負数は不可です。
- 月キーは正規表現 `[0-9]{4}-(0[1-9]|1[0-2])` に完全一致する必要があります。
- 次の場合は `BudgetError` になり、`main` がメッセージを stderr に出して**終了コード 2** で終わります。
  - ファイルが読めない
  - JSON が不正
  - 最上位が object でない
  - `months` が object でない
  - 月キーが不正
  - 金額が不正
- 予算は CSV より先に読みます。両方不正なら予算のエラーだけが出ます。

## 何と比べているか(`core.py:125-135`, `__init__.py:105`)

比べる対象は `monthly_totals(rows)` が返す `{月: {カテゴリ: 円}}` です。これは `--report` の集計と同じものです。通常表示のカテゴリ合計(`total_by_category`)とは別物で、`--budget` は常に月別で比べます。

- 判定は `actual > limit` です。ちょうど予算と同額なら警告しません。
- 予算にないカテゴリは対象外です。
- カテゴリ名は CSV と完全一致で照合します。
- 警告の形式は `警告: 2026-11 food 1,000円超過 (予算 1,000 / 実績 2,000)` です。

## `--memo` / `--category` との組み合わせ

- **`--memo`**: 予算判定は絞り込み**後**の行で行います。`totals` は memo で絞った `rows` から作るので、一致した行だけの月別合計が予算と比較されます。そのため、絞り込みで合計が減ると警告が出なくなることがあります。`tests/test_memo.py:66` がこれを確認しています。memo に一致する行がなければ totals が空になり、警告も出ません。
- **`--category`**: 予算判定には**影響しません**。`--category` は表示用の `totals_by_cat` だけを絞ります。`find_overruns` に渡す `totals` は絞らないので、`--category food` と指定しても rent など他カテゴリの超過警告は出ます。逆に stdout は food だけでも、警告は全カテゴリ分です。
- **`--report`**: 併用できます。stdout は月別表示になり、警告は同じです。

`--category` が警告を絞らないことは README にも `--help` にも書かれていません。コードを読んで分かった挙動で、`--memo` のヘルプにだけ「`--budget` の警告も絞り込み後の集計が対象」とあります。また、この組み合わせを確認するテストは見当たりませんでした。意図した仕様かどうかは、確認してみてください。
