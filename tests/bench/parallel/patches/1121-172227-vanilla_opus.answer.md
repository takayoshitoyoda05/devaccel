`load_csv` と `monthly_totals` に、まだ無かった端のケースのテストを足して commit しました(`56d80d6`)。変更したのは `tests/test_core.py` だけで、実装はそのままです。テストは 80 件成功、3 件は不具合を記録した期待どおりの失敗(xfail)で、ruff の検査も通っています。

**足したテスト**
- **`load_csv`**:
  - 空ファイルと、ヘッダだけのファイル
  - memo 列が無い CSV
  - category 前後の空白除去
  - 引用符の中のカンマや改行
  - 余分な列
  - 空行があっても行番号がずれないこと
  - CRLF 改行
  - 金額・日付の不正な値
  - 必須の列が無いときに全行がエラーになること
  - エラーメッセージのつなぎ方
- **`monthly_totals`**:
  - 空のリスト
  - 年をまたぐ月の並び順
  - 同じ月で年が違う場合
  - 同じ金額のときは先に出た順になること
  - マイナスで打ち消し合って 0 になったカテゴリも残ること
  - 入力リストを書き換えないこと

**見つけた不具合(直していません)**

次の 3 件は `xfail(strict=True)` のテストとして残しました。直すとテストが成功に変わって失敗扱いになるので、修正したときに xfail の印を外してください。
1. **BOM 付き CSV が全行エラーになる**(`core.py:52`)。`encoding="utf-8"` で開いているため、1 列目の名前が `\ufeffdate` になり、「列 date がありません」になります。Excel で保存した CSV では普通に起きます。`utf-8-sig` で開けば直ります。
2. **複数行にまたがる行でエラーが出ると、行番号がその行の最後の行を指す**(`core.py:58`)。`reader.line_num` は読み終えた時点の行番号です。たとえばメモ欄に改行が入った 2 行目の日付が不正だと、「3」と報告されます。
3. **西暦 1000 年より前の日付だと月のキーが崩れる**(`core.py:75`)。`strftime("%Y")` がゼロ埋めしないので `"999-01"` になり、`"2026-01"` より後ろに並びます。予算ファイルの月の形式(YYYY-MM)とも合いません。実際にはまず起きません。

**仕様として意図どおりか確認したい点**

次の値は今はエラーにならず受け付けられます。意図どおりか分からないので、テストでは固定していません。
- 日付の `20261101` や `2026-W47-1`(週番号での書き方)
- 金額の全角数字 `１００`、`1_000`、` 100 ` のような前後の空白(一方で日付は前後に空白があるとエラーになり、扱いが揃っていません)
- 空の category
- マイナスの金額
