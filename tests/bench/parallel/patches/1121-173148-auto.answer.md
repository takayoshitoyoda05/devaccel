追加したのは `load_csv` と `monthly_totals` の端のケースです。たとえば空ファイル、CRLF、引用符内の改行、不正な日付や金額、年またぎの月順、同額カテゴリの順序などを固定しています。

見つけた不具合の候補(直していません):
- **UTF-8 BOM 付き CSV が全行エラーになります。** Excel 出力の CSV で起きます。先頭の列名が `\ufeffdate` になり、全行が「列 date がありません」で拒否されます。`encoding="utf-8-sig"` にすれば直ります。
- **空カテゴリ `""` がそのまま受理されます。** `2026-11-01,,100,` が `category=""` の行になり、集計に `""` の行が出ます。
- **`20261101` 形式の日付が受理されます。** Python 3.11 以降の `fromisoformat` の仕様で、意図的かどうかは不明です。
- **負の金額が受理されます。** 返金用途なら妥当ですが、仕様としては未確定です。負の金額が通ることは今回のテストで固定しました(`-500` と、同一カテゴリ内で相殺して 0 になる合計)。

BOM・空カテゴリ・20261101 形式の日付は、仕様が決まっていないためテストで固定していません。どう扱うか決まったら、直すのと同時にテストも足します。
