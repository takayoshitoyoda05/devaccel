# devaccel-batch

## 自動で使うかの判断(ユーザーに確認しない)
次をすべて満たすときファンアウトにする。1 つでも外れたら普通に 1 セッションで順に実装する(その後 devaccel-pr)。
- **独立した作業が 4 件以上**(3 件以下は逐次のほうが速い・安い。実測 D14/D17)。
- 各件が **別のファイル** を作る・変える(同じファイルを触る件どうしは 1 件にまとめる)。
- 各件が S〜M(L = 3 ファイル超・設計判断あり・認証/DB/削除/秘密情報 は並列にしない。design スキル)。
- 仕様が依頼文から書き下せる(書けない件はユーザーに質問してから)。
- 作業ツリーがきれい(未コミットの変更がある・main 以外の作業ブランチにいるなら、先に devaccel-pr で片付けるか逐次にする)。

## 設計書(依頼がざっくりしているとき。番号付きの仕様なら書かない)
`docs/design/YYYYMMDD-<短い名前>.md` に Write する。そのまま単位への指示書になり、PR にも入る(人は差分ではなく判断一覧・例の表・証拠を見る)。散文でなく表と短い行で書く(1 件 25 行・例 8 行・共通前提 8 行まで)。件の中で `1.` 形式の番号付きリストは使わない(件の区切りになる)。形:

```
# <名前>
目的: … / やらないこと: …
共通前提: 標準ライブラリのみ・既存ファイル不変・使う型 `…`
判断一覧(依頼から決められない点の既定。最大 5、影響の大きい順。代替を添える): D1 … (代替: …) / D2 …

1. `src/x.py` + `tests/test_x.py` — `def f(a: T) -> U`
規則: R1 … / R2 並びは …、同点は … / R3 もし〈入力の種類〉なら〈例外 or スキップ〉
例(全行がテストになる):
| ID | 入力 | 出力 / 例外 | 規則 |
| E1-1 | … | … | R1 |
不変条件: P1 …(例の全行で成り立つこと)
```
書くときの確かめ(書面には結果だけ):
- 拒否・除外する規則ごとに「それで拒否されてしまう正当な入力は?」を 1 つ問い、答えを判断一覧か例に入れる(例: 負の金額を拒否 → 返金は?)。
- その件が触れる領域の端を例に入れる: 金額(符号・0・桁区切り・通貨記号・全角)/ CSV・構文(引用符内の区切りと改行・BOM・空行・列の過不足)/ 日付(月末・閏・範囲の端)/ 並び(同点・グループをまたぐ混在)/ 集合(空・1 件・重複)。
- 例の無い規則、規則の無い例を残さない。
L 規模なら設計書を見せて承認を待つ(design スキル)。それ以外は待たずに進む。

**速い書き方(既定)**: 親は骨組みだけを `docs/design/YYYYMMDD-<名前>.md` に Write する — 見出し・目的/やらないこと・共通前提・判断一覧(ここは親が決める)と、件ごとに `1. \`src/x.py\` + \`tests/test_x.py\` — <何をするか 1〜3 行。依頼の言葉と判断一覧の該当 D を残す>`。そして 2 を `--design` 付きで実行する: ファンアウトが件ごとに設計者(sonnet)を同時に起動して上の形の節(規則・例の表・不変条件)を書かせ、骨組みを完成した設計書で置き換えてから単位を動かす(設計書は PR に入る)。親が全文を書くと 70〜80 秒かかる。

## 手順(ファンアウト)
1. **ユーザーの依頼文が既に件ごとの仕様(`1.` `2.` … と番号付き)なら、何も書かずに** 2 で依頼ファイルを `.devaccel/prompt.md` にする(実行の瞬間にガードがユーザーの依頼文をそのまま書き出す。事前に確認・作成しない。打ち直しの時間とコストが要らない)。番号付きでなければ、`.claude/skills/devaccel-batch/reference.md` の書き方を読んでから、依頼を `.devaccel/tasks.md` に **毎回 Write で上書きする**(前回のファイルが残っていても読まずに書き直す)。依頼文が既に件ごとの仕様になっていれば、そのまま写す(言い換え・要約しない)。親はコードを読み込みすぎない: 名前・型・ファイルの場所を確かめる程度にとどめる(中身は単位が読み、名指しした小さなファイルは自動で埋め込まれる。親の読み込みはそのままコストになる)。
2. 単独のコマンドで実行する(パイプ・リダイレクト・`&&` を付けない。出力は数行。Bash の timeout は 600000。サンドボックスの外で動くよう設定済み。単位はそれぞれサンドボックス内):
   `python3 .claude/hooks/devaccel_batch.py .devaccel/prompt.md --branch batch/<短い名前>`(または `docs/design/<名前>.md`・`.devaccel/tasks.md`。骨組みなら `docs/design/<名前>.md --branch batch/<名前> --design`)
   - `error:` で止まったら(作業ツリーが汚い・ブランチ名など)直してから再実行。`--dry-run` は何も動かさずに点検だけする。
3. 短く報告する(3〜5 行。単位ごとの詳細は PR 本文とログにある): PR の URL とラベル、`units: X/Y ok`、外れた件と理由(`check fail`・`touches protected files` など)。外れた件は、ユーザーに伝えたうえで逐次で実装し直してよい(手で取り繕って ok に見せない)。マージは人。
