# 端のケース集(設計書の規則・判断を書くときに引く)

使い方:
- 最初に、既存のコードに同じ概念の型・関数(例: 予算の型、月別集計、読み込み)があるかを確かめる。あれば新しく作らずに受け取って使う(同じものを二重に持たない)。
- 件が触れる領域の節だけ読む。
- 各問いに、規則(R)か判断(D)で答える。受け付ける書き方は列挙する(「数値なら」ではなく `△` `▲` `(500)` `-` `−` のように書く)。
- 答えが「拒否」なら、その拒否で弾かれる正当な入力を 1 つ考え、判断一覧に入れる。
- 例は判断を固定する行だけ書く(1 件 3 行まで)。

## 公開する関数の引数(どの機能でも)
- 型: `bool` は `int` の仲間なので明示的に弾くか。`float`(`1234.0`・`nan`)・`str`・`None` を受けるか、`TypeError` にするか。
- 範囲: 負の金額・負の上限・0・割合の 0 / 100 % / 100 % 超(しきい値)を受けるか。弾くなら `ValueError` で、どの引数が悪いかを書く。
- 弾くと決めた入力は、それぞれテストにする(黙って妙な結果を返さない)。

## 金額・数値の文字列
- 符号はどう書かれるか: `-300`、`−300`(U+2212)、`△500`、`▲500`、`(500)`、`500-`。負数は返金として受けるか、拒否するか、別に扱うか。
- 記号は: `¥` `￥` `円` `JPY`、桁区切り `,` `，`、空白(全角を含む)。
- 全角は: `１２３`、`１，２３４`。NFKC で正規化するか。
- 0、空欄、`-`、`—` の扱い。小数(`12.5`)を拒否するか、丸めるか。
- 区切り記号を含む値が CSV で引用されていない場合(`1,234円` が 2 列に割れる)。列数の誤りとして報告するか、修復するか。

## CSV・表形式の入力
- 区切り: `,` かタブか(自動判定するか)。BOM(`﻿`)。改行コード。
- 引用: 引用符の中の区切りと改行。報告する行番号は、そのレコードの開始行か。
- ヘッダー: 列名の別名(例: 日付/利用日/取引日/date、金額/利用金額/出金額/amount、摘要/メモ/利用店名/ご利用店名/description)。大文字小文字と前後の空白。必須列が無いときの扱い。
- 金額が 2 列に分かれる形式(出金/入金、支払/預入)。入金だけの行はスキップか。
- 列の不足・過剰、空行、ヘッダーだけ、空入力(空の結果を返すか、例外か)。
- 1 行に誤りが複数ある場合、すべて報告するか、最初の 1 つか。誤りの報告に含めるもの(行番号・列名・元の値)。

## 日付・期間
- 書式: `2026/1/5`、`2026-01-05`、区切りの混在、和暦、時刻付き。存在しない日付(2/30)。
- 月の加算: 月末(1/31 の翌月)、閏年(2024-02-29)、12 月から 1 月。
- 毎月の繰り返しの基準日: 最後の日付か、系列の中の最大の日か(31・31・28 の次は 3/31 か 3/28 か)。
- 期間の端を含むか(以上・以下)。開始と終了が逆のとき。
- 欠けた月がある系列、同じ月に 2 回ある系列。

## 繰り返し・グループ化
- 何で同一とみなすか: カテゴリ、金額、メモ(正規化: NFKC・大文字小文字・空白・末尾の番号)。
- 同じカテゴリ・同じ金額の別物(例: 5 日と 20 日に来る 2 つのサブスク)。
- 金額の変化(値上げ・数 % の揺れ)を同じ系列とみなすか。返金・負の金額を系列に混ぜるか。
- 何件(何か月)以上で繰り返しとみなすか。最小件数の下限の検査。

## 並び・集合・集計
- 並び順と同点の扱い(安定か、第 2 キーは何か)。
- 空、1 件、重複。片方にだけあるキー(前月にだけ・今月にだけあるカテゴリ)。
- 0 での割り算(前月 0 の増減率)。空の月。
- 期間を並べて比べるとき、途中の月がデータに無い場合: 空の月(全カテゴリ 0)として比べるか(1 月にあって 2 月に無ければ 2 月に「なくなった」)、飛ばすか。最初の期間は何と比べるか。

## 検索・条件式
- AND・OR・NOT の入れ子と優先順位。空の AND(真)と空の OR(偽)。
- 範囲は端を含むか。下限が上限より大きいとき。
- 文字列の一致: 部分一致か、大文字小文字・全角半角を区別するか。空文字の条件。
- 不正な条件(未知のキー、型違い)は例外か。
